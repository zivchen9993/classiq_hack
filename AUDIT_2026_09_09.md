## Contradictions and non-canonical values

1. The README Classiq table reports QAOA-X `P(opt)=1.00%`, feasibility `8.3%`
   and QAOA-XY `P(opt)=8.70%`. `WRITEUP.md` reports `0.00%`, `22.8%` and
   `0.20%` for those fields. `quantum_solver_results` reports `0.00%`, `22.0%`
   and `0.70%`. These are three incompatible accounts of what is described as
   the same 18-qubit, depth-2 Classiq experiment. None is canonical until a
   provenance-complete rerun is executed.
2. The write-up's local statevector table reports QAOA-XY `P(opt)=17.09%` at
   depth 1 and `17.16%` at depth 5. `visualize.py` embeds different fallback
   values, `20.11%` and `16.11%`, for the ansatz figure.
3. `visualize.py` manually embeds the complete 36-qubit depth series
   `[0.170, 0.842, 1.215, 2.000, 5.290]%`, the transfer series, and Classiq
   fallback points. The figures are therefore not generated solely from a
   saved result record, despite comments implying that they reuse measured
   benchmark output.
4. The `855x` comparison uses one QAOA-X statevector result while the random
   amplification statements use a different denominator. The README and
   write-up do not consistently distinguish a circuit shot, an exact
   statevector probability, a greedy restart, and a classical objective
   evaluation.
5. README calls the constrained XY mixer “ours”. The mixer is prior art; the
   project contribution is its antenna-specific formulation, implementation
   and validation.
6. README and WRITEUP say the 36-qubit full statevector is out of reach for
   “any” simulator. That is too broad. The accurate claim is that a dense
   36-qubit statevector is beyond commodity-memory hardware, while the
   `T^S` representation is a classical feasible-subspace simulation and not a
   scalable quantum implementation.
7. README's primary narrative is a snapshot problem and advertises mean-SINR
   and throughput gains without putting the corresponding handover-failure
   increase in the same headline. The continuation requirement makes the
   temporal problem primary and requires operational KPIs beside every
   surrogate result.
8. `STATUS.md` correctly records that the candidate-chain temporal objective
   is exactly solvable by dynamic programming and that its surrogate gain did
   not improve exact network KPIs. README and the opening of WRITEUP do not
   carry that negative result into the main narrative.
9. `benchmark_results` and `quantum_solver_results` are unstructured terminal
   transcripts. They lack commit/dirty state, dependency versions, backend,
   complete seed/schedule data and machine-readable resource fields.
10. The saved candidate-chain temporal JSON has useful configuration and raw
    metrics, but predates the canonical schema and lacks the required git,
    software, backend and circuit-resource provenance.

## Canonicalization decision

- All pre-2026-09-09 outputs are **historical**, not canonical headline data.
- Schema `temporal-antenna-benchmark/1.0.0` in `result_schema.py` is the only
  canonical format for new runs.
- Resource fields remain separate: classical objective evaluations, parameter
  search circuit executions, quantum executions, sampling shots, synthesis
  time, wall time and circuit metrics.
- The initial `06_12_50_utc` integration smoke exposed that the legacy
  `subspace_cost` adapter omitted the new explicit temporal-edge field. Its
  classical rows remain diagnostic raw output, but its quantum rows are
  **superseded and non-canonical**. A regression test now requires the reduced
  quantum cost to match the direct objective on every tiny trajectory.
- A replacement direct-problem smoke run is a tiny correctness result; it is
  not evidence of solution-quality scaling or quantum advantage.
- Documentation and final figures must not be reconciled to new headline
  values until Classiq validation and the intermediate multi-seed benchmark
  have canonical saved outputs.
